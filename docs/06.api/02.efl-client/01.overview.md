## Purpose

`EflClient` is the main entry point for most integrations.
It orchestrates calls to the underlying [API clients](../03.clients/02.process-api-client.md) and exposes high-level methods that match common ecommerce scenarios, such as:

- Starting a leasing process for an order.
- Calculating basic offers for a basket of assets.
- Submitting customer data and statements.
- Initialising identity verification and checking its status.
- Sending leads and contact forms.

Internally it uses the low-level clients from the `Api` namespace and converts between models defined in the [`Model`](../04.models/01.overview.md) namespace.

## Construction

You typically construct `EflClient` once and reuse it:

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Config;
use Imoli\EflLeasingSdk\EflClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;

$config = Config::sandbox(
    apiKey: 'your-sandbox-api-key',
    baseUrl: 'https://leasingonlineapi-sandbox.efl.com.pl'
);

$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

$httpClient = new GuzzleHttpAdapter($guzzle);

$client = new EflClient($config, $httpClient);
```

### Class definition

- **Namespace**: `Imoli\EflLeasingSdk`
- **Class**: `final class EflClient`
- **Constructor**:
  - `public function __construct(Config $config, HttpClientInterface $httpClient, ?RequestLoggerInterface $logger = null)`
- **Internal composition**:
  - Creates an [`EflHttpClient`](../07.http.md#eflhttpclient) using the provided [`Config`](../../05.configuration.md), [`HttpClientInterface`](../07.http.md#httpclientinterface) and optional [`RequestLoggerInterface`](../07.http.md#requestloggerinterface).
  - Instantiates and holds:
    - [`ProcessApiClient`](../03.clients/02.process-api-client.md)
    - [`CalculationApiClient`](../03.clients/03.calculation-api-client.md)
    - [`CustomerApiClient`](../03.clients/04.customer-api-client.md)
    - [`ProductsApiClient`](../03.clients/05.products-api-client.md)
    - [`LeadApiClient`](../03.clients/06.lead-api-client.md)
    - [`TestingApiClient`](../03.clients/08.testing-api-client.md)
    - [`RestorationApiClient`](../03.clients/07.restoration-api-client.md)
    - [`DemoApiClient`](../03.clients/09.demo-api-client.md)

Most applications should depend only on `EflClient` and the model classes described in the [models overview](../04.models/01.overview.md), without instantiating low-level API clients directly.

## Typical usage pattern

A typical flow using `EflClient` looks like this:

1. Obtain an authentication token.
2. Start a leasing process.
3. Calculate offers for a basket.
4. Submit customer data and statements.
5. Perform identity verification and pay‑by‑link steps.
6. Optionally send leads or restore processes.

The high-level methods are designed to be used from controller or service code in your application, keeping the SDK concerns isolated from the rest of your domain logic.
