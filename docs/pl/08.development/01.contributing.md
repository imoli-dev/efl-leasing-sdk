## Wytyczne dotyczące współtworzenia

Podczas współtworzenia SDK prosimy o przestrzeganie następujących ogólnych zasad:

- Cały kod, komentarze i dokumentacja muszą być pisane w języku **angielskim** (z wyjątkiem nazw własnych, takich jak „EFL Leasing”).
- Przestrzegaj stylu kodowania **PSR-12**.
- Używaj ścisłego typowania we wszystkich plikach PHP (`declare(strict_types=1);`).
- Preferuj jasne, jawne typy i unikaj używania `mixed`, chyba że jest to absolutnie konieczne.

## Przepływ pracy deweloperskiej

1. Stwórz fork i sklonuj repozytorium.
2. Zainstaluj zależności:

   ```bash
   composer install
   ```

3. Wprowadź zmiany w gałęzi funkcjonalnej (feature branch).
4. Uruchom testy i analizę statyczną przed otwarciem pull requesta:

   ```bash
   composer test
   composer phpstan
   composer cs-check
   ```

5. Tam, gdzie to możliwe, dodaj lub zaktualizuj testy, aby pokryć swoje zmiany.

## Styl kodu

Używaj dostarczonej konfiguracji PHP-CS-Fixer:

```bash
composer cs-fix
```

Uruchom to polecenie przed zatwierdzeniem zmian (commit), aby zapewnić spójne formatowanie.

## Komunikaty commitów

- Używaj jasnych, opisowych komunikatów commitów w języku angielskim.
- Preferuj prefiksy zgodne z konwencją conventional commits, takie jak `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`.
