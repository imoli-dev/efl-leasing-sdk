## Przegląd

Ten przewodnik przeprowadzi Cię przez pełny przepływ leasingowy w aplikacji backendowej:

1. Pobranie tokena autoryzacyjnego i rozpoczęcie procesu.
2. Obliczenie ofert dla koszyka i zaakceptowanie wybranego wariantu.
3. Przesłanie danych klienta i dodatkowych oświadczeń.
4. Inicjalizacja weryfikacji tożsamości i obsługa pay-by-link.
5. Śledzenie zmian procesu i statusu końcowego.
6. Przywrócenie sesji klienta po podpisaniu umowy.

Przykłady kodu celowo skupiają się na podstawowych wywołaniach SDK.

## 1. Od koszyka do rozpoczęcia procesu

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Config;
use Imoli\EflLeasingSdk\EflClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;

// Konfiguracja (sandbox)
$config = Config::sandbox(
    apiKey: getenv('EFL_API_KEY'),
    baseUrl: 'https://leasingonlineapi-sandbox.efl.com.pl'
);

$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

$httpClient = new GuzzleHttpAdapter($guzzle);
$client = new EflClient($config, $httpClient);

// 1) Pobranie tokena Bearer używanego w kolejnych wywołaniach
$partnerId = getenv('EFL_PARTNER_ID');
$token = $client->getAuthToken($partnerId);

// 2) Rozpoczęcie procesu leasingowego dla bieżącego zamówienia
$process = $client->startProcess(
    positiveReturnUrl: 'https://example.com/efl/success',
    negativeReturnUrl: 'https://example.com/efl/failure',
    bearerToken: $token
);

// Zapisz identyfikator transakcji z obiektu $process do późniejszego użycia
$processTransactionId = /* wyodrębnij transactionId z $process */;
```

## 2. Wybór i akceptacja oferty

```php
use Imoli\EflLeasingSdk\Model\Calculation\AssetToCalculation;
use Imoli\EflLeasingSdk\Model\Calculation\OfferItem;
use Imoli\EflLeasingSdk\Model\Calculation\ItemDetail;

// Zbuduj koszyk na podstawie swojego zamówienia
$itemDetail = new ItemDetail(
    guid: 'item-guid-1',
    description: 'Example asset'
    // ... dodatkowe pola wymagane przez model
);

$offerItem = OfferItem::builder('offer-item-guid-1')
    ->withItemDetail($itemDetail)
    // skonfiguruj inne parametry finansowe w razie potrzeby
    ->build();

$basket = AssetToCalculation::builder('basket-guid-1')
    ->addOfferItem($offerItem)
    ->build();

// Oblicz podstawową ofertę
$offerResponse = $client->calculateBasicOffer($basket, $token);

// Zaprezentuj warianty klientowi i pozwól mu wybrać jeden
$selectedCalculationId = /* wybrany identyfikator kalkulacji */;
$selectedVariantId = /* wybrany identyfikator wariantu */;

// Zaakceptuj wybrany wariant
$client->acceptCalculation(
    transactionId: $processTransactionId,
    calculationId: $selectedCalculationId,
    calculationVariantId: $selectedVariantId,
    basketCalculation: null,
    bearerToken: $token
);
```

## 3. Dane klienta i oświadczenia

```php
use Imoli\EflLeasingSdk\Model\Customer\Address;
use Imoli\EflLeasingSdk\Model\Customer\Company;
use Imoli\EflLeasingSdk\Model\Customer\CustomerData;
use Imoli\EflLeasingSdk\Model\Customer\CustomerDataStatement;
use Imoli\EflLeasingSdk\Model\Customer\EmailAddress;
use Imoli\EflLeasingSdk\Model\Customer\Phone;

// Zbuduj dane klienta na podstawie własnych modeli domenowych / formularzy
$company = Company::builder('company-guid', '1234567890')
    ->addEmail(new EmailAddress('email-guid', 'contact@example.com', 'work'))
    ->addPhone(new Phone('phone-guid', '+48', '123456789', 'mobile', 'mobile'))
    ->addAddress(new Address(
        'addr-guid',
        'Headquarters',
        'registered_office',
        'Warsaw',
        'Main St',
        '1',
        '00-001',
        'PL'
    ))
    ->addStatement(new CustomerDataStatement('stmt-guid', true, 'gdpr'))
    ->build();

$customerData = CustomerData::builder($processTransactionId, 42)
    ->withCompany($company)
    ->build();

// Prześlij główne dane klienta
$client->submitCustomerData($customerData, $token);

// Opcjonalnie prześlij dodatkowe oświadczenia
$additionalStatements = [
    new CustomerDataStatement('stmt-marketing', true, 'marketing'),
];

$client->submitCustomerStatements(
    transactionId: $processTransactionId,
    statements: $additionalStatements,
    bearerToken: $token
);
```

## 4. Weryfikacja tożsamości i pay-by-link

```php
use Imoli\EflLeasingSdk\Model\Verification\VerificationInitializationParams;

// Zbuduj parametry weryfikacji zgodnie z dokumentacją EFL
$params = VerificationInitializationParams::builder('order-uuid')
    // skonfiguruj zgodnie z regułami weryfikacji EFL
    ->build();

// Inicjalizuj weryfikację tożsamości
$verificationResult = $client->initializeIdentityVerification(
    $processTransactionId,
    $params,
    $token
);

$redirectUrl = $verificationResult->getRedirectUrl();

// Przekieruj klienta pod adres $redirectUrl w celu przeprowadzenia weryfikacji tożsamości

// Opcjonalnie zainicjuj płatność pay-by-link w odpowiednim punkcie przepływu
$client->initiatePayByLinkPayment($processTransactionId, $token);
```

## 6. Przywrócenie sesji po podpisaniu umowy

Po podpisaniu umowy może być konieczne przywrócenie sesji klienta
przy użyciu danych zwróconych przez EFL (na przykład identyfikatora zamówienia pay-by-link lub identyfikatora transakcji).

```php
use Imoli\EflLeasingSdk\Model\Restoration\AuthenticationRestorationResult;

// Przywróć sesję za pomocą identyfikatora zamówienia pay-by-link
$restorationResult = $client->restoreCustomerSessionByOrderId($payByLinkOrderId);

// Lub przywróć sesję bezpośrednio za pomocą identyfikatora transakcji po podpisaniu
$restorationResultAfterSigning = $client->restoreSessionAfterSigning($processTransactionId);

// Zdecyduj, jak kontynuować, na podstawie akcji przywracania
$action = $restorationResult->getReauthenticationAction(); // enum ReauthenticationAction

switch ($action) {
    case 'None':
        // Sesja może zostać przywrócona bez dodatkowej akcji użytkownika
        break;
    case 'Reauthenticate':
        // Poproś użytkownika o ponowne uwierzytelnienie przed kontynuowaniem
        break;
    // obsłuż inne wartości enum zdefiniowane w modelu
}
```

To kończy pełny opis procesu.
W rzeczywistej aplikacji powinieneś połączyć ten przepływ z odpowiednią obsługą błędów,
logowaniem i ponowieniami, jak opisano w dedykowanym przewodniku obsługi błędów.
