## Modele obliczeniowe

Znajdują się w `Model\Calculation`:

- `AssetToCalculation` – reprezentuje koszyk aktywów do użycia w obliczeniu oferty.
- `OfferItem` – pojedynczy element w koszyku z parametrami finansowymi.
- `ItemDetail` – szczegółowe dane opisowe o aktywie.
- `EsbCalculateBasicOfferRestReturn` – wynik podstawowego obliczenia oferty, zawierający warianty oferty.

Te modele są zazwyczaj budowane przy użyciu budowniczych (builders):

```php
use Imoli\EflLeasingSdk\Model\Calculation\AssetToCalculation;
use Imoli\EflLeasingSdk\Model\Calculation\OfferItem;
use Imoli\EflLeasingSdk\Model\Calculation\ItemDetail;

$itemDetail = new ItemDetail(
    guid: 'item-guid-1',
    description: 'Example asset'
    // ... other required fields
);

$offerItem = OfferItem::builder('offer-item-guid-1')
    ->withItemDetail($itemDetail)
    ->build();

$basket = AssetToCalculation::builder('basket-guid-1')
    ->addOfferItem($offerItem)
    ->build();
```

## Modele klienta i leadów

Znajdują się w `Model\Customer` oraz `Model\Lead`:

- `CustomerData` – dane klienta najwyższego poziomu dla transakcji.
- `Company` / `Person` – szczegóły osoby prawnej lub fizycznej.
- `Address`, `EmailAddress`, `Phone` – dane kontaktowe.
- `CustomerDataStatement`, `StatementLead` – oświadczenia i zgody.
- `ContactData` – dane dla leadów i formularzy kontaktowych.

Przykład:

```php
use Imoli\EflLeasingSdk\Model\Customer\Address;
use Imoli\EflLeasingSdk\Model\Customer\Company;
use Imoli\EflLeasingSdk\Model\Customer\CustomerData;
use Imoli\EflLeasingSdk\Model\Customer\CustomerDataStatement;
use Imoli\EflLeasingSdk\Model\Customer\EmailAddress;
use Imoli\EflLeasingSdk\Model\Customer\Phone;

$company = Company::builder('company-guid', '1234567890')
    ->addEmail(new EmailAddress('email-guid', 'contact@example.com', 'work'))
    ->addPhone(new Phone('phone-guid', '+48', '123456789', 'mobile', 'mobile'))
    ->addAddress(new Address('addr-guid', 'Headquarters', 'registered_office', 'Warsaw', 'Main St', '1', '00-001', 'PL'))
    ->addStatement(new CustomerDataStatement('stmt-guid', true, 'gdpr'))
    ->build();

$customerData = CustomerData::builder('tx-1', 42)
    ->withCompany($company)
    ->build();
```

## Modele procesu i weryfikacji

Znajdują się w `Model\Process` oraz `Model\Verification`:

- `AuthenticateResponse` – wynik operacji uwierzytelniania / pobierania tokenu oraz przywracania procesu.
- `FoicProcessStateResponse` – odpowiedź o stanie procesu używana podczas śledzenia zmian procesu.
- `VerificationInitializationParams` / `VerificationInitializationResult` – wejście i wyjście dla inicjalizacji weryfikacji tożsamości.
- `VerificationResult`, `ResultBlueMedia`, `StatusBlueMedia`, `BlueMediaProcessStateResponse` – modele reprezentujące wyniki weryfikacji tożsamości oraz status BlueMedia.

Te modele pozwalają na pracę z typowanymi reprezentacjami stanu procesu i weryfikacji zamiast surowych tablic.

## Modele produktów

Znajdują się w `Model\Products`:

- `Sector`, `ProductClass`, `ProductType` – hierarchiczne wpisy katalogu produktów (sektor → klasa → typ).
- `Brand`, `ModelInfo` – informacje o marce i modelu dla aktywów.
- `SectorProductInfoTree`, `BrandProductInfoTree` – struktury drzewiaste zwracane przez punkty końcowe informacji o produktach.

Te modele są zazwyczaj zwracane przez metody związane z produktami w `EflClient`, takie jak `getSectorClassAndType()` oraz `getBrandModelByProductType()`.

## Modele przywracania

Znajdują się w `Model\Restoration`:

- `AuthenticationRestorationResult` – wynik przywrócenia sesji klienta.
- `ReauthenticationAction` – enum opisujący następną akcję do podjęcia po przywróceniu (np. czy użytkownik powinien zostać ponownie uwierzytelniony).

Te modele są zwracane przez metody przywracania sesji i pomagają zdecydować, jak kontynuować przepływ użytkownika po podpisaniu.

## Model błędu

Znajduje się w `Model\Error`:

- `ProblemDetails` – reprezentacja szczegółów błędu API zgodnie z RFC 7807.

Instancje `ProblemDetails` są dostępne w `ApiException` i powinny być używane do logowania i diagnostyki.
