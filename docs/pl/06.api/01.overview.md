## API wysokiego i niskiego poziomu

SDK udostępnia dwa główne sposoby interakcji z EFL Leasing Online API:

- **Klient wysokiego poziomu**: [`EflClient`](02.efl-client/01.overview.md)
  - Orkiestruje typowe przepływy ecommerce.
  - Ukrywa większość szczegółów HTTP i modeli za wygodnymi metodami.
- **Klienci API niskiego poziomu** w przestrzeni nazw `Api`:
  - [`CalculationApiClient`](03.clients/03.calculation-api-client.md)
  - [`CustomerApiClient`](03.clients/04.customer-api-client.md)
  - [`ProcessApiClient`](03.clients/02.process-api-client.md)
  - [`ProductsApiClient`](03.clients/05.products-api-client.md)
  - [`LeadApiClient`](03.clients/06.lead-api-client.md)
  - [`RestorationApiClient`](03.clients/07.restoration-api-client.md)
  - [`TestingApiClient`](03.clients/08.testing-api-client.md)
  - [`DemoApiClient`](03.clients/09.demo-api-client.md)

[`EflClient`](02.efl-client/01.overview.md) używa tych niskopoziomowych klientów wewnętrznie. Zazwyczaj możesz pozostać przy API wysokiego poziomu i korzystać z klientów niskopoziomowych tylko wtedy, gdy potrzebujesz większej kontroli lub zaawansowanych scenariuszy.

## Modele

Dane żądań i odpowiedzi są reprezentowane przez niemutowalne obiekty wartości (value objects) w przestrzeni nazw `Model`.
Są one pogrupowane według domen:

- `Model\Calculation` – żądania i wyniki kalkulacji.
- `Model\Customer` – dane klienta, adresy, e-maile, telefony i oświadczenia.
- `Model\Lead` – leady i dane kontaktowe.
- `Model\Process` – odpowiedzi procesowe i uwierzytelniające.
- `Model\Products` – drzewa katalogu produktów.
- `Model\Verification` – dane wejściowe i wyjściowe weryfikacji tożsamości.
- `Model\Restoration` – wyniki przywracania sesji.
- `Model\Error` – [`ProblemDetails`](04.models/44.problem-details.md) dla strukturalnych odpowiedzi o błędach API.

Większość modeli żądań udostępnia metodę `::builder()`, która zwraca płynny builder ułatwiający konstrukcję obiektów.

## Obsługa błędów

Wszystkie błędy specyficzne dla SDK dziedziczą po [`EflLeasingException`](06.errors.md#eflleasingexception).
Najważniejsze podklasy to:

- [`ApiException`](06.errors.md#apiexception-and-problemdetails) – błędy na poziomie API (HTTP 4xx/5xx) z dostępem do [`ProblemDetails`](04.models/44.problem-details.md).
- [`HttpException`](06.errors.md#httpexception) – błędy na poziomie transportu (błędy sieciowe, timeouty, nieprawidłowe odpowiedzi).

Powinieneś przechwytywać te wyjątki na granicach swojej aplikacji i tłumaczyć je na odpowiednie odpowiedzi HTTP, logi lub komunikaty dla użytkownika.
