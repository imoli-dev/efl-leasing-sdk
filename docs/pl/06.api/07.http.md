## Przegląd

SDK nie komunikuje się bezpośrednio z EFL Leasing Online API.
Zamiast tego używa małej abstrakcji HTTP, która rozdziela:

- [`Config`](../05.configuration.md) – bazowy URL i ustawienia uwierzytelniania.
- [`HttpClientInterface`](#httpclientinterface) – Twoja biblioteka HTTP (Guzzle, Symfony HttpClient, własna).
- [`EflHttpClient`](#eflhttpclient) – pomocnik wysokiego poziomu, który wie, jak budować adresy URL, nakładać nagłówki i mapować błędy.
- [`HttpResponse`](#httpresponse) – prosty obiekt wartości (value object) używany przez SDK.

Ta sekcja opisuje te bloki konstrukcyjne, abyś mógł bezpiecznie podłączyć własną implementację klienta HTTP.

## HttpClientInterface

[`HttpClientInterface`](#httpclientinterface) to jedyny kontrakt, którego SDK potrzebuje do wykonywania żądań HTTP:

```php
use Imoli\EflLeasingSdk\Exception\HttpException;
use Imoli\EflLeasingSdk\Http\HttpClientInterface;
use Imoli\EflLeasingSdk\Http\HttpResponse;

interface HttpClientInterface
{
    /**
     * @param non-empty-string $method Metoda HTTP, np. GET, POST.
     * @param non-empty-string $url Bezwzględny adres URL zawierający schemat i hosta.
     * @param array<string, string> $headers
     * @param string|null $body
     *
     * @throws HttpException Gdy żądanie nie powiedzie się na poziomie transportu.
     */
    public function request(
        string $method,
        string $url,
        array $headers = [],
        ?string $body = null,
    ): HttpResponse;
}
```

Implementacja jest odpowiedzialna za:

- Wykonanie żądania HTTP z podaną metodą, adresem URL, nagłówkami i opcjonalnym body.
- Zwrócenie obiektu [`HttpResponse`](#httpresponse) dla wszystkich żądań (nawet gdy kod statusu to 4xx/5xx).
- Rzucenie `HttpException`, gdy wystąpi błąd na poziomie transportu (awarie sieci, timeouty, błędy niskopoziomowe biblioteki).

## HttpResponse

[`HttpResponse`](#httpresponse) to mały, niemutowalny obiekt wartości używany przez SDK i udostępniany przez niskopoziomowych klientów API:

```php
use Imoli\EflLeasingSdk\Http\HttpResponse;

final class HttpResponse
{
    public function __construct(int $statusCode, array $headers, string $body);

    public function getStatusCode(): int;

    /** @return array<string, string> */
    public function getHeaders(): array;

    public function getBody(): string;
}
```

- `statusCode` – numeryczny kod statusu HTTP zwrócony przez serwer.
- `headers` – płaska tablica asocjacyjna nagłówków odpowiedzi.
- `body` – surowe body odpowiedzi jako ciąg znaków.

Metody wysokiego poziomu w [`EflClient`](02.efl-client/01.overview.md) zazwyczaj deserializują body za Ciebie.
Klienci niskiego poziomu udostępniają `HttpResponse`, dzięki czemu możesz ręcznie sprawdzać i przetwarzać dane, gdy jest to potrzebne.

## EflHttpClient

[`EflHttpClient`](#eflhttpclient) łączy Twoją implementację [`Config`](../05.configuration.md) i [`HttpClientInterface`](#httpclientinterface) z semantyką EFL Leasing Online API:

```php
use Imoli\EflLeasingSdk\Config;
use Imoli\EflLeasingSdk\Http\EflHttpClient;
use Imoli\EflLeasingSdk\Http\HttpClientInterface;
use Imoli\EflLeasingSdk\Http\HttpResponse;
use Imoli\EflLeasingSdk\Http\RequestLoggerInterface;

final class EflHttpClient
{
    public function __construct(
        Config $config,
        HttpClientInterface $httpClient,
        ?RequestLoggerInterface $logger = null,
    );

    /** @return HttpResponse */
    public function requestWithApiKey(
        string $method,
        string $path,
        array $query = [],
        array $headers = [],
        ?string $body = null,
    ): HttpResponse;

    /** @return HttpResponse */
    public function requestWithBearerToken(
        string $method,
        string $path,
        string $token,
        array $query = [],
        array $headers = [],
        ?string $body = null,
    ): HttpResponse;

    /** @return HttpResponse */
    public function request(
        string $method,
        string $path,
        array $query = [],
        array $headers = [],
        ?string $body = null,
    ): HttpResponse;
}
```

Kluczowe zadania:

- **Budowanie adresów URL** – łączy `Config::getBaseUrl()` z relatywnymi ścieżkami takimi jak `/lon/api/v1/...` i serializuje parametry zapytania.
- **Uwierzytelnianie**:
  - `requestWithApiKey()` dodaje nagłówek `ApiKey` z [`Config`](../05.configuration.md).
  - `requestWithBearerToken()` dodaje nagłówek `Authorization: Bearer ...`.
- **Logowanie (opcjonalne)** – wywołuje `RequestLoggerInterface` przed i po żądaniu.
- **Mapowanie błędów** – dla kodów statusu HTTP `>= 400` rzuca `ApiException` z przetworzonymi danymi `ProblemDetails`, jeśli są dostępne.

Zazwyczaj nie tworzysz instancji [`EflHttpClient`](#eflhttpclient) bezpośrednio.
Jest on tworzony wewnątrz [`EflClient`](02.efl-client/01.overview.md) oraz w niskopoziomowych klientach API.

## Wbudowane adaptery

SDK dostarczane jest z gotowymi adapterami dla popularnych bibliotek HTTP.
Wszystkie one implementują [`HttpClientInterface`](#httpclientinterface), więc możesz je wymieniać bez zmiany reszty kodu.

### GuzzleHttpAdapter

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;
use Imoli\EflLeasingSdk\Http\HttpClientInterface;

$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

/** @var HttpClientInterface $httpClient */
$httpClient = new GuzzleHttpAdapter($guzzle);
```

- Wymaga pakietu `guzzlehttp/guzzle`.
- Wyłącza automatyczne wyjątki przy kodach 4xx/5xx (`http_errors` is set to `false`), aby `EflHttpClient` mógł spójnie obsługiwać błędy API.

### SymfonyHttpAdapter

```php
use Imoli\EflLeasingSdk\Http\Adapter\SymfonyHttpAdapter;
use Symfony\Component\HttpClient\HttpClient;

$symfonyClient = HttpClient::create();
$httpClient = new SymfonyHttpAdapter($symfonyClient);
```

- Wymaga pakietu `symfony/http-client`.
- Adaptuje obiekt odpowiedzi Symfony do `HttpResponse`, spłaszczając nagłówki wielowartościowe.

### NativeHttpClient

```php
use Imoli\EflLeasingSdk\Http\HttpClientInterface;
use Imoli\EflLeasingSdk\Http\NativeHttpClient;

/** @var HttpClientInterface $httpClient */
$httpClient = new NativeHttpClient();
```

`NativeHttpClient` jest minimalną, tymczasową implementacją.
W tej chwili rzuca `HttpException` dla wszystkich wywołań i jest przeznaczony jedynie jako punkt wyjścia.
Dla rzeczywistych integracji powinieneś:

- Użyć adapterów Guzzle lub Symfony, albo
- Dostarczyć własną, solidną implementację `HttpClientInterface`.

## Własne adaptery

Jeśli używasz innej biblioteki klienta HTTP, zaimplementuj [`HttpClientInterface`](#httpclientinterface) samodzielnie.
Krótka lista kontrolna:

- Nie rzucaj wyjątków przy kodach HTTP 4xx/5xx – zawsze zwracaj `HttpResponse`.
- Rzucaj `HttpException` dla błędów sieciowych/transportowych lub błędnej konfiguracji.
- Normalizuj nagłówki odpowiedzi do prostej tablicy `array<string, string>`.
- Zachowaj surowe body odpowiedzi dokładnie w takiej formie, w jakiej zostało zwrócone przez serwer.

Gdy masz już implementację, przekaż ją do [`EflClient`](02.efl-client/01.overview.md) wraz z [`Config`](../05.configuration.md):

```php
use Imoli\EflLeasingSdk\Config;
use Imoli\EflLeasingSdk\EflClient;
use Imoli\EflLeasingSdk\Http\HttpClientInterface;

/** @var HttpClientInterface $httpClient */
$config = Config::sandbox('your-sandbox-api-key');

$client = new EflClient($config, $httpClient);
```
