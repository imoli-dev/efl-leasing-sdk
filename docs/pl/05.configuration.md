## Config i Environment

Obiekt wartości [`Config`](06.api/02.efl-client/01.overview.md#construction) opisuje sposób, w jaki SDK łączy się z API EFL Leasing Online:

- Klucz API używany do uwierzytelniania.
- Środowisko (sandbox lub produkcja).
- Bazowy adres URL API.

Użyj metod fabrykujących, aby utworzyć instancje konfiguracji:

```php
use Imoli\EflLeasingSdk\Config;

// Konfiguracja sandbox (bazowy adres URL jest wybierany automatycznie)
$sandboxConfig = Config::sandbox(
    apiKey: 'your-sandbox-api-key',
);

// Konfiguracja produkcyjna (musisz podać bazowy adres URL)
$productionConfig = Config::production(
    apiKey: 'your-production-api-key',
    baseUrl: 'https://leasingonlineapi.efl.com.pl',
);
```

### Referencja Config

Obiekt wartości `Config` przechowuje:

- `apiKey` (`string`) – klucz API używany do uwierzytelniania Twoich żądań.
- `environment` ([`Environment`](#environment-enum)) – jedna z wartości `Environment::Sandbox` lub `Environment::Production`.
- `baseUrl` (`string`) – bazowy adres URL API EFL Leasing Online (bez końcowego `/`).

`Config::sandbox()` i `Config::production()` dbają o normalizację bazowego adresu URL i wybór właściwej wartości środowiska.

### Enum Environment

Enum [`Environment`](#environment-enum) jest używany wewnętrznie do rozróżniania środowisk sandbox i produkcyjnego:

```php
use Imoli\EflLeasingSdk\Enum\Environment;

$env = Environment::Sandbox;    // API sandbox
$env = Environment::Production; // API produkcyjne
```

Zazwyczaj nie musisz ręcznie tworzyć instancji `Environment`. Jest ona wyrowadzana z użytej metody fabrykującej:

- `Config::sandbox()` → `Environment::Sandbox`
- `Config::production()` → `Environment::Production`

## Wybór klienta HTTP

SDK nie wykonuje bezpośrednio żądań HTTP. Zamiast tego polega na [`HttpClientInterface`](06.api/07.http.md#httpclientinterface), który musisz zaimplementować lub zaadaptować.

Możesz wybierać pomiędzy:

- **Adapterem Guzzle (`GuzzleHttpAdapter`)**
- **Adapterem Symfony HttpClient (`SymfonyHttpAdapter`)**
- **Własną implementacją** `HttpClientInterface`

### Adapter Guzzle

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;

$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

$httpClient = new GuzzleHttpAdapter($guzzle);
```

### Adapter Symfony HttpClient

```php
use Imoli\EflLeasingSdk\Http\Adapter\SymfonyHttpAdapter;
use Symfony\Component\HttpClient\HttpClient;

$symfonyClient = HttpClient::create();
$httpClient = new SymfonyHttpAdapter($symfonyClient);
```

### Własna implementacja

Jeśli używasz innej biblioteki HTTP, samodzielnie zaimplementuj [`HttpClientInterface`](06.api/07.http.md#httpclientinterface).

Twoja implementacja jest odpowiedzialna za:

- Wykonywanie żądań HTTP z podaną metodą, adresem URL, nagłówkami i treścią.
- Zwracanie odpowiedzi zgodnej z abstrakcją `HttpResponse` SDK.
- Rzucanie `HttpException` (lub podklas `EflLeasingException`) w przypadku błędów na poziomie transportu, jeśli to właściwe.

Szczegóły znajdziesz w referencji **API → HTTP**.

## Inicjalizacja EflClient

Gdy masz już [`Config`](06.api/02.efl-client/01.overview.md#construction) oraz implementację [`HttpClientInterface`](06.api/07.http.md#httpclientinterface), utwórz głównego klienta:

```php
use Imoli\EflLeasingSdk\EflClient;

$client = new EflClient($sandboxConfig, $httpClient);
```

Zazwyczaj tworzysz pojedynczą instancję [`EflClient`](06.api/02.efl-client/01.overview.md) na środowisko i używasz jej wielokrotnie w swojej aplikacji.

## Timeouty i niezawodność

Systemy produkcyjne powinny konfigurować rozsądne timeouty na poziomie klienta HTTP:

- Całkowity timeout żądania (np. 15–30 sekund).
- Timeout połączenia (np. 5–10 sekund).

Samo SDK nie implementuje ponowień (retries) ani mechanizmów circuit breaker.
Jeśli potrzebujesz tych funkcji, skonfiguruj je w swoim kliencie HTTP lub w kodzie aplikacji.

## Logowanie żądań i odpowiedzi

W celach debugowania lub audytu możesz podłączyć implementację `RequestLoggerInterface`.
Logger otrzymuje szczegóły zarówno żądania, jak i odpowiedzi, i może być używany do:

- Zapisywania logów do plików lub systemów logowania strukturalnego.
- Wysyłania błędów do usługi monitoringu.
- Inspekcji surowych odpowiedzi podczas diagnozowania problemów.

Unikaj logowania wrażliwych danych (takich jak pełne dane klienta) na produkcji.

## Przełączanie między sandboxem a produkcją

Typowym wzorcem jest:

- Używanie konfiguracji i poświadczeń sandbox w środowiskach nieprodukcyjnych (lokalne, staging).
- Używanie konfiguracji i poświadczeń produkcyjnych w środowisku produkcyjnym.

Możesz to opakować we własną fabrykę lub usługę konfiguracyjną.

Upewnij się, że nigdy nie używasz poświadczeń ani adresów URL sandbox na produkcji.

## Najlepsze praktyki

- Przechowuj klucze API i identyfikatory partnerów w zmiennych środowiskowych, a nie w systemie kontroli wersji.
- Skonfiguruj rozsądne timeouty w swoim kliencie HTTP (zarówno całkowity timeout żądania, jak i timeout połączenia).
- Używaj konfiguracji i poświadczeń sandbox tylko w środowiskach nieprodukcyjnych.
- Używaj ponownie pojedynczej instancji `EflClient` na środowisko zamiast tworzyć nową przy każdym żądaniu.
