## Wymagania

SDK jest skierowane do nowoczesnych aplikacji PHP i ma następujące minimalne wymagania:

- PHP **>= 8.1** (zalecane **8.2** lub nowsze)
- `ext-json`
- Composer do zarządzania zależnościami

Samo SDK nie zależy od konkretnej implementacji klienta HTTP, ale będziesz potrzebować:

- Guzzle (`guzzlehttp/guzzle`), lub
- Symfony HttpClient (`symfony/http-client`), lub
- Własnej implementacji `HttpClientInterface`.

## Instalacja SDK

Zainstaluj pakiet przez Composer:

```bash
composer require imoli-dev/efl-leasing-sdk
```

Spowoduje to dodanie `imoli-dev/efl-leasing-sdk` do pliku `composer.json` i zainstalowanie wszystkich wymaganych zależności.

Główna przestrzeń nazw SDK to:

- `Imoli\EflLeasingSdk\`

z autoloadowaniem PSR-4 z katalogu `src/`.

### Instalacja z repozytorium Git

Jeśli wolisz zainstalować SDK bezpośrednio z repozytorium Git zamiast z Packagist, możesz skonfigurować repozytorium VCS w swoim `composer.json`:

```json
{
  "repositories": [
    {
      "type": "vcs",
      "url": "https://github.com/imoli-dev/efl-leasing-sdk"
    }
  ],
  "require": {
    "imoli-dev/efl-leasing-sdk": "dev-master"
  }
}
```

Powyższy przykład używa gałęzi `master` (`dev-master`) i zawsze dostarcza najnowsze commity z tej gałęzi.

Jeśli chcesz zablokować projekt na **konkretnej wersji otagowanej**, zmień odpowiednio ograniczenie, na przykład:

```json
{
  "repositories": [
    {
      "type": "vcs",
      "url": "https://github.com/imoli-dev/efl-leasing-sdk"
    }
  ],
  "require": {
    "imoli-dev/efl-leasing-sdk": "1.2.3"
  }
}
```

Możesz także użyć zakresu wersji, takiego jak `"^1.2"`, jeśli chcesz pozostać na stabilnej linii major/minor, otrzymując jednocześnie kompatybilne poprawki błędów.

Po zaktualizowaniu `composer.json` uruchom:

```bash
composer update imoli-dev/efl-leasing-sdk
```

To podejście jest przydatne, gdy chcesz przetestować nieopublikowane zmiany z repozytorium GitHub `imoli-dev/efl-leasing-sdk` lub gdy musisz polegać na forku lub konkretnym tagu z Git.

## Instalacja adapterów klienta HTTP

Jeśli chcesz użyć jednego z wbudowanych adapterów HTTP, zainstaluj odpowiedni pakiet.

### Guzzle

```bash
composer require guzzlehttp/guzzle
```

Następnie skonfiguruj adapter:

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;

$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

$httpClient = new GuzzleHttpAdapter($guzzle);
```

### Symfony HttpClient

```bash
composer require symfony/http-client
```

Następnie skonfiguruj adapter:

```php
use Imoli\EflLeasingSdk\Http\Adapter\SymfonyHttpAdapter;
use Symfony\Component\HttpClient\HttpClient;

$symfonyClient = HttpClient::create();
$httpClient = new SymfonyHttpAdapter($symfonyClient);
```

### Własny klient HTTP

Jeśli Twój projekt używa innego stosu HTTP, zaimplementuj `HttpClientInterface` zdefiniowany przez SDK.
Przewodnik **Integracja HTTP** oraz dokumentacja **API** wyjaśniają wymagane metody i oczekiwane zachowanie.

## Instalacja narzędzi deweloperskich

Do rozwoju SDK i współtworzenia projektu możesz również zainstalować:

- Rozszerzenie Xdebug lub PCOV dla pokrycia kodu testami.
- Narzędzia skonfigurowane w skryptach `composer.json`:
  - `composer test` – uruchomienie zestawu testów.
  - `composer test:coverage` – wygenerowanie raportu pokrycia.
  - `composer phpstan` – uruchomienie analizy statycznej.
  - `composer cs-check` – sprawdzenie standardów kodowania.
  - `composer cs-fix` – automatyczna naprawa standardów kodowania.

Te narzędzia **nie są wymagane**, aby używać SDK jako zależności w Twojej aplikacji.
