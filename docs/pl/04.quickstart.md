## Cel

Ten szybki start pokazuje minimalny, realistyczny przepływ backendowy dla oferowania EFL Leasing jako metody płatności:

1. Konfiguracja SDK i klienta HTTP.
2. Pobranie tokena uwierzytelniającego.
3. Rozpoczęcie procesu leasingowego.
4. Obliczenie podstawowej oferty dla koszyka przedmiotów.

Przykład celowo skupia się na "ścieżce szczęśliwej" (happy path). Obsługa błędów i przypadki brzegowe są omówione w dedykowanych sekcjach.

## 1. Przygotowanie konfiguracji i klienta HTTP

```php
use GuzzleHttp\Client as GuzzleClient;
use Imoli\EflLeasingSdk\Config;
use Imoli\EflLeasingSdk\EflClient;
use Imoli\EflLeasingSdk\Http\Adapter\GuzzleHttpAdapter;

// 1. Konfiguracja (sandbox)
$config = Config::sandbox(
    apiKey: 'your-sandbox-api-key',
    baseUrl: 'https://leasingonlineapi-sandbox.efl.com.pl'
);

// 2. Klient HTTP (Guzzle)
$guzzle = new GuzzleClient([
    'timeout' => 30,
    'connect_timeout' => 10,
]);

$httpClient = new GuzzleHttpAdapter($guzzle);

// 3. Główny klient SDK
$client = new EflClient($config, $httpClient);
```

## 2. Uwierzytelnienie i rozpoczęcie procesu

```php
// Zazwyczaj skonfigurowane w Twojej aplikacji
$partnerId = 'your-partner-id';
$successUrl = 'https://example.com/efl/success';
$failureUrl = 'https://example.com/efl/failure';

// 1) Pobranie tokena uwierzytelniającego
// Token Bearer zwrócony przez getAuthToken(), używany ponownie w kolejnych wywołaniach
$token = $client->getAuthToken($partnerId);

// 2) Rozpoczęcie procesu leasingowego
$process = $client->startProcess(
    positiveReturnUrl: $successUrl,
    negativeReturnUrl: $failureUrl,
    token: $token
);

// Zwrócony obiekt procesu zawiera identyfikatory i adresy URL potrzebne w kolejnych krokach.
```

## 3. Budowanie koszyka i obliczanie podstawowej oferty

```php
use Imoli\EflLeasingSdk\Model\Calculation\AssetToCalculation;
use Imoli\EflLeasingSdk\Model\Calculation\OfferItem;
use Imoli\EflLeasingSdk\Model\Calculation\ItemDetail;

// Przykładowy koszyk: pojedynczy przedmiot z podstawowymi danymi
$itemDetail = new ItemDetail(
    guid: 'item-guid-1',
    description: 'Example asset',
    // ... dodatkowe wymagane pola zdefiniowane w modelu
);

$offerItem = OfferItem::builder('offer-item-guid-1')
    ->withItemDetail($itemDetail)
    // skonfiguruj inne parametry finansowe w razie potrzeby
    ->build();

$basket = AssetToCalculation::builder('basket-guid-1')
    ->addOfferItem($offerItem)
    ->build();

// Oblicz podstawową ofertę dla koszyka
$offerResponse = $client->calculateBasicOffer($basket, $token);

// $offerResponse jest obiektem wartości EsbCalculateBasicOfferRestReturn z wariantami oferty.
```

## 4. Co dalej?

W typowym backendzie:

1. Pokazujesz użytkownikowi dostępne warianty z `$offerResponse`.
2. Po wybraniu oferty przez użytkownika zbierasz dane klienta i oświadczenia.
3. Przesyłasz dane klienta i przechodzisz do weryfikacji tożsamości / pay‑by‑link.

- **API → Modele** – zobacz [przegląd modeli](06.api/04.models/01.overview.md) dla szczegółów dotyczących kalkulacji, klienta i innych modeli.
