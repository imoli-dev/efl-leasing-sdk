## High-level vs low-level APIs

The SDK exposes two main ways of interacting with the EFL Leasing Online API:

- **High-level client**: [`EflClient`](02.efl-client/01.overview.md)
  - Orchestrates typical ecommerce flows.
  - Hides most HTTP and model details behind convenient methods.
- **Low-level API clients** in the `Api` namespace:
  - [`CalculationApiClient`](03.clients/03.calculation-api-client.md)
  - [`CustomerApiClient`](03.clients/04.customer-api-client.md)
  - [`ProcessApiClient`](03.clients/02.process-api-client.md)
  - [`ProductsApiClient`](03.clients/05.products-api-client.md)
  - [`LeadApiClient`](03.clients/06.lead-api-client.md)
  - [`RestorationApiClient`](03.clients/07.restoration-api-client.md)
  - [`TestingApiClient`](03.clients/08.testing-api-client.md)
  - [`DemoApiClient`](03.clients/09.demo-api-client.md)

[`EflClient`](02.efl-client/01.overview.md) uses these low-level clients internally. You can typically stay on the high-level API and only drop to low-level clients when you need more control or advanced scenarios.

## Models

Request and response payloads are represented by immutable value objects in the `Model` namespace.
They are grouped by domain:

- `Model\Calculation` – calculation requests and results.
- `Model\Customer` – customer data, addresses, emails, phones and statements.
- `Model\Lead` – leads and contact data.
- `Model\Process` – process and authentication responses.
- `Model\Products` – product catalogue trees.
- `Model\Verification` – identity verification inputs and outputs.
- `Model\Restoration` – session restoration results.
- `Model\Error` – [`ProblemDetails`](04.models/44.problem-details.md) for structured API error responses.

Most request models provide a `::builder()` method that returns a fluent builder for easier construction.

## Error handling

All SDK-specific errors extend [`EflLeasingException`](06.errors.md#eflleasingexception).
The most important subclasses are:

- [`ApiException`](06.errors.md#apiexception-and-problemdetails) – API-level errors (HTTP 4xx/5xx) with access to [`ProblemDetails`](04.models/44.problem-details.md).
- [`HttpException`](06.errors.md#httpexception) – transport-level failures (network errors, timeouts, invalid responses).

You should catch these exceptions at your application boundaries and translate them into appropriate HTTP responses, logs or user-facing messages.
