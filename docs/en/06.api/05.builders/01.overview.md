## Namespace and purpose

The `Imoli\EflLeasingSdk\Builder` namespace contains **fluent builders** for the main request models used when calling the EFL Leasing Online API.
They provide a more readable and less error‑prone way of constructing complex payloads than assembling nested arrays by hand.

Builders are most often used together with [`EflClient`](../02.efl-client/01.overview.md) methods from the `clients` section and the corresponding models from the `models` section.

## Groups of builders

- **Calculation** – basket and offer‑related payloads:
  - [`AssetToCalculationBuilder`](02.asset-to-calculation-builder.md) – builds [`AssetToCalculation`](../04.models/02.asset-to-calculation.md) (basket for basic offer calculation),
  - [`OfferItemBuilder`](03.offer-item-builder.md) – builds [`OfferItem`](../04.models/03.offer-item.md) entries for the basket,
  - [`ItemDetailBuilder`](04.item-detail-builder.md) – builds [`ItemDetail`](../04.models/04.item-detail.md) metadata items for offer items.

- **Customer** – company and customer‑related payloads:
  - [`CustomerDataBuilder`](05.customer-data-builder.md) – builds [`CustomerData`](../04.models/15.customer-data.md) for `/Customer/PostCustomerDataForLon`,
  - [`CompanyBuilder`](06.company-builder.md) – builds [`Company`](../04.models/16.company.md) with contact details, addresses and statements,
  - [`PersonBuilder`](07.person-builder.md) – builds [`Person`](../04.models/17.person.md) linked to the company,
  - [`AddressBuilder`](08.address-builder.md) – builds [`Address`](../04.models/18.address.md) entries,
  - [`EmailAddressBuilder`](09.email-address-builder.md) – builds [`EmailAddress`](../04.models/19.email-address.md) entries,
  - [`PhoneBuilder`](10.phone-builder.md) – builds [`Phone`](../04.models/20.phone.md) entries,
  - [`CustomerDataStatementBuilder`](11.customer-data-statement-builder.md) – builds [`CustomerDataStatement`](../04.models/21.customer-data-statement.md) entries,
  - [`IdentityDocumentBuilder`](12.identity-document-builder.md) – builds [`IdentityDocument`](../04.models/22.identity-document.md) entries.

- **Lead** – contact / lead‑related payloads:
  - [`ContactDataBuilder`](13.contact-data-builder.md) – builds [`ContactData`](../04.models/23.contact-data.md) for `/Lead/SendContactForm`,
  - [`ProspectBuilder`](14.prospect-builder.md) – builds [`Prospect`](../04.models/24.prospect.md) data,
  - [`StatementLeadBuilder`](15.statement-lead-builder.md) – builds [`StatementLead`](../04.models/25.statement-lead.md) consent entries.

- **Verification** – identity verification payloads:
  - [`VerificationInitializationParamsBuilder`](16.verification-initialization-params-builder.md) – builds [`VerificationInitializationParams`](../04.models/37.verification-initialization-params.md),
  - [`VerificationResultBuilder`](17.verification-result-builder.md) – builds [`VerificationResult`](../04.models/39.verification-result.md),
  - [`PostVerificationCodeBuilder`](18.post-verification-code-builder.md) – builds [`PostVerificationCode`](../04.models/43.post-verification-code.md).

## When to use builders

Use builders when:

- you want a **fluent API** instead of constructing nested arrays or calling large model constructors directly,
- you need to enforce **required fields** – most builders validate required data in `build()` and throw a `\LogicException` if it is missing,
- you want a single place where **default values** and composition rules are encoded.

You can always construct models directly (see the `models` section), but builders are recommended for application‑level code that prepares payloads for `EflClient`.
